# P2 도입·유지보수 지원 제안 초안

작성일: 2026-10-11. 이 문서는 R10의 지원 범위와 가격을 검증하기 위한 **미확정 제안서**다. 실제 고객 채택, 구매 의향, 유료 파일럿, 계약 또는 SLA가 확보되었다는 의미가 아니다. 사용자 지시에 따라 합성 데이터와 확인 가능한 패키지 버전으로 기술 검증을 진행했다. 로드맵의 상업적 gate(실제 채택 2팀, 유료 요청 1건, 파일럿 또는 계약 확인)는 아직 충족되지 않았다.

## 지원할 결과

고객이 승인한 schema에 공유 정책을 연결하고 CI에서 누락 후보를 찾으며, 테넌트 격리·미리보기·삭제 후 검증·완료 재시도를 재현하는 것을 지원한다. 고객의 신원·주체 확인, 보존 근거·기간 결정, 운영 승인과 배포는 고객의 담당자가 맡는다. 법률 자문, GDPR/CCPA 준수 보장, 등록하지 않은 데이터의 완전 삭제는 판매 범위에 넣지 않는다.

첫 유료 제안은 [고정 Nestarc 조합](nestarc-composition.md)과 단일 PostgreSQL, 제한된 크기의 data-subject 실행을 기준으로 한다. 다른 nestarc 패키지 도입은 필수가 아니다. 지원 시작 전에 고객의 exact lockfile, schema, transaction 연결, artifact 저장소와 재현 가능한 비식별 fixture를 합의한다. 동일한 지원 범위와 가격을 모든 고객에게 이미 제공하고 있다고 표현하지 않는다.

## 가격과 작업량 가설

가격은 고객 지불의사나 시장 평균을 측정한 결과가 아니다. 아래 금액과 작업시간은 첫 제안에서 검증할 가설이며 세금·계약 조건·업무 범위는 견적에서 확정한다.

| 제안 | 가설 가격 | 포함 작업과 한도 | 고객과 합의할 수락 기준 |
| --- | --- | --- | --- |
| 도입 진단 | 50만 원, 1회 | 최대 5시간, 앱 1개·DB 1개. schema/정책 gap 분석, 지원 밖 경로와 필요한 migration 문서 | 고객 담당자가 범위·제약을 검토하고 도입/보류 결정 가능 |
| 도입 파일럿 | 200만 원, 2주 | 최대 20시간. 합의한 엔티티와 fixture, transaction 연결, CI 검사, 장애 재현 및 인수인계 | tenant 교차 변경 0건, 합의한 정책 결함 검출, callback/프로세스 실패 후 복구를 고객 환경에서 재현 |
| 유지보수 | 월 50만 원 | 월 최대 4시간, 고정 버전 조합 1개. 오류 분류, 재현, 범위 안의 패치·업그레이드 검토 | 지원 작업시간·재발률·응답 목표 달성률을 월별 확인 |

추가 커넥터, 타 DB, 대규모 관계 그래프, schema 전체 재설계, 운영 대행, 24시간 온콜은 별도 범위다. 포함 시간을 넘는 작업은 범위와 비용을 사전에 다시 합의한다. 계약 전에는 실제 가격표·청구·결제 경로를 활성화하지 않는다.

## 응답 목표 가설

지원 시간 가설은 한국 공휴일을 제외한 평일 10:00–18:00 KST다. 아래는 최초 분류 응답의 목표이며 해결 시간 또는 가용성 SLA가 아니다. 연락 채널과 담당자를 계약에 정하고, 계약되지 않은 OSS 이슈에 이 목표를 약속하지 않는다.

| 우선순위 | 예시 | 최초 분류 목표 | 우선 제공할 내용 |
| --- | --- | --- | --- |
| 긴급 | 지원 조합에서 재현되는 tenant 경계 위반 또는 예상하지 않은 데이터 변경 | 지원 시간 4시간 이내 | 실행 중단/범위 축소 권고, 영향 확인 방법, 재현·수정 계획 |
| 높음 | 요청이 복구되지 않거나 CI·배포가 지원 조합에서 차단됨 | 영업일 1일 이내 | 오류 단계, 안전한 재시도 가능 여부, 우회 또는 패치 계획 |
| 일반 | 정책 추가, schema 변경, 문서·사용법 문의 | 영업일 3일 이내 | 적용 예제, 지원 범위, 일정 또는 별도 견적 |

의도하지 않은 삭제나 credential 노출이 있는 경우 공개 이슈에 원본 행, 토큰, DB 접속 정보, artifact bytes를 올리지 않도록 접수 양식에서 안내한다. 고객이 제공하는 재현 자료는 가능한 한 합성 데이터로 제한하고, 필요한 접근 권한·보존 기간은 접수 때 합의한다.

## 파일럿 측정표

다음 필드는 고객과 파일럿을 시작할 때 빈 값에서 기록한다. 현재 문서에는 가상 고객이나 구매 성과를 기입하지 않는다.

| 필드 | 수집 기준 |
| --- | --- |
| pilot ID / 고객 동의·시작일 | 익명 내부 ID, 기술 담당·승인자, 테스트 데이터 사용 범위 |
| 기술 조합 | Node/Nest/Prisma/PostgreSQL/각 패키지 exact 버전, lockfile hash, schema revision |
| 실행 범위 | 엔티티 수, 정책 필드 수, 보존 예외, 미등록 저장소, 요청당 행/bytes의 분포 |
| 최초 도입 시간 | 설치부터 첫 tenant 격리·미리보기·실행 검증 성공까지 실제 작업시간. 대기시간은 구분 |
| 비교 기준 | 같은 schema를 기존 SQL/서비스로 처리하는 실제 작업 기록. 추정이면 추정으로 표시 |
| 변경 대응 | 신규/변경 필드 수, 발견한 결함과 오탐, 조사·수정·리뷰 시간 |
| 실행 신뢰성 | 실제/합성 요청 구분, 다른 tenant 변경 건수, 검증 실패, artifact/통지 재시도, 복구 시간 |
| 운영 비용 | 메모리·시간 초과·재시작 재현 조건, 엔지니어 개입 횟수·소요시간, 지원 노동시간 |
| 반복 사용 | 다음 실제 요청 또는 schema 변경에 다시 사용했는지, 재사용한 정책/연동, 이탈 사유 |
| 상업적 근거 | 예산 소유자 확인, 제안 가격, 서면 유료 요청/계약/입금의 날짜와 내부 참조. 동의 없는 원문 공개 금지 |
| 고객 수락 | 완료 기준별 고객 확인, 남은 제약, 운영 배포 여부·승인자 |

도입 시간 감소나 절감액은 동일 조건의 실제 측정이 있을 때만 계산한다. 다운로드 수와 GitHub 지표를 고객 수·지불의사로 바꾸지 않는다. 합성 테스트 통과는 실제 운영 성공 건수에 포함하지 않는다.

## 계속 투자할 조건

1. 실제 채택 2팀과 유료 요청 1건을 확인하고, 최소 한 팀과 범위·수락 기준·가격을 문서로 합의한다.
2. 유료 파일럿 또는 계약을 확인한 뒤, 지원 작업시간이 포함 시간과 가격으로 지속 가능한지 점검한다.
3. 파일럿의 반복 요청이나 schema 변경에서 재사용을 확인한다. 부족하면 무료 코어의 문서·호환성·품질을 유지하며 신규 유료 기능 확장을 보류한다.

이 문서 작성과 합성 조합 검증으로 1–3번을 완료 처리하지 않는다. 고객 연락, 견적 발송, 계약 체결 또는 결제는 별도로 명시적인 사용자 지시가 있을 때 진행한다.
